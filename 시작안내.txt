RTSP 카메라 녹화 - Linux x86_64 / v2.5 / 2026-11-17

처음 사용하는 경우
1. ZIP을 원하는 새 폴더에 풉니다. bin/ffmpeg를 포함한 폴더 구조를 유지하세요.
2. RTSP_recorder 폴더에서 터미널을 열고 실행합니다.
   bash 실행.sh
   같은 브라우저 화면: bash 브라우저실행.sh
   별도 데스크톱 창: bash 실행_GUI.sh (python3-tk 필요)
3. 처음에는 카메라 IP·계정·비밀번호·날씨 지역이 비어 있습니다.
   장비 설정에서 실제 카메라를 직접 등록하거나 운영 setup.ini를 선택하세요.
   admin이나 특정 IP를 자동으로 넣지 않습니다. 인증 없는 카메라는 계정을 비워 둘 수 있습니다.
4. 저장 폴더·RTSP 포트·영상 경로·시간표·녹화 방식을 확인하고 저장합니다.
   카메라 등록 전에도 다른 설정의 초안을 저장할 수 있지만 녹화는 시작할 수 없습니다.
5. 설정 검사 → 5분 시험 녹화 → 영상 재생 확인 후 예약 녹화를 시작합니다.
   날씨 조건이나 예보 조회를 사용할 때만 시간표 · 날씨에서 지역을 직접 선택하세요.

새 설치의 녹화 기본값
- 한국 시간 06:30-07:30 / 10:00-11:00 / 12:00-13:00 / 17:00-18:00 / 21:00-22:00
- 예약 구간마다 MP4 한 파일(recording_mode=window), ./recordings 저장
- 자동 삭제 꺼짐, 날씨 조건 꺼짐. 카메라를 등록하고 시작해야 실제 녹화합니다.
- 분할이 필요하면 장비 설정에서 ‘일정 길이로 파일 분할’을 선택하고 분 수를 입력하세요.
- window 모드에서는 segment_minutes가 남아 있어도 분할하지 않습니다.
- 연결이 끊겼다 복구되면 새 파일이 생길 수 있습니다. 영상은 재인코딩하지 않습니다.
- 한 번만 녹화에서는 저장된 카메라 한 대를 선택할 수도 있으며 예약 대상은 바뀌지 않습니다.

기존 설정은 보존합니다
- recording.json이 없을 때만 초기 설정을 생성합니다. 운영 JSON은 ZIP에 넣지 않습니다.
- 기존 IP·계정·지역이 옛 예제와 같더라도 실제 운영값일 수 있으므로 자동 삭제하지 않습니다.
- 이전 JSON에 recording_mode가 없고 분할 길이가 있으면 기존 split 동작을 유지합니다.
  전체 구간 한 파일이 필요하면 화면에서 ‘예약 구간마다 한 파일’을 선택해 저장하세요.
- 빈 설정으로 시험하려면 기존 운영 폴더를 지우지 말고 새 폴더에 배포본을 풉니다.

사진 캡처
- 브라우저의 이미지 캡처에서 저장된 카메라·프로필을 고르고 PNG 한 장을 저장합니다.
- 사진은 영상 output_dir과 별도로 recording.json 옆 snapshots/카메라/날짜에 저장합니다.
- H.264/H.265 해독과 PNG 저장을 지원하는 일반 FFmpeg가 필요합니다.
  Ubuntu에 없으면: sudo apt install ffmpeg
- RTSP 연결·인증에는 기존 녹화용 FFmpeg를 사용합니다. 패키지를 자동 설치하지 않습니다.

허브 관리
- 관리 IP·계정과 이미 구성된 enp2* 또는 파생 VLAN의 관리 인터페이스·소스 IP를 입력합니다.
- 쓰기 지원: NEXTU NTK-9528 계열, 모델 식별값 POE9728MDTL2, 펌웨어 V200SP10241024.
- 상태 조회 → 변경 내용 미리보기 → 명시적 적용 순서로 진행합니다.
- ED 연결·광 업링크·링·관리/제어 VLAN은 보호하며 PC IP·Netplan·LTE를 변경하지 않습니다.
- 포트 껐다 켜기는 데이터 링크 제어입니다. 카메라 전원이나 PoE 제어가 아닙니다.
  포트가 꺼진 동안 해당 카메라 녹화·센터 영상이 끊깁니다.
- 기존 카메라용 VLAN만 선택할 수 있으며 관리 IP는 현재 관리 대역 안에서만 변경합니다.
- 변경 전 설정과 결과는 switch_backups에 보관합니다. 백업을 외부에 공유하지 마세요.
- 업데이트 자체는 실제 허브나 카메라 설정을 변경하지 않습니다.

카메라 IP · 계정 관리 (v2.5)
- 브라우저의 카메라 IP · 계정에서 현재 네트워크·모델·MAC을 조회합니다.
- 지원 PG-ABS08041402 카메라의 IP·마스크·게이트웨이 또는 관리자 비밀번호를 미리 보고 확인 후 적용합니다.
- 초기 상태가 확인된 카메라 한 대에만 최초 비밀번호를 설정합니다. 같은 초기 IP 장비는 먼저 한 대씩 분리하세요.
- 제조사 지정 admin 계정은 확인된 초기 상태의 최초 비밀번호 등록에만 사용합니다. 일반 등록 계정은 직접 입력합니다.
- 장비 확인 후 선택한 카메라의 녹화기 접속 정보도 갱신합니다. 결과가 부분 완료이면 현재 장비와 설정을 확인하세요.
- 실제 비밀번호를 바꾸면 센터·NVR 등 다른 수신 프로그램의 계정도 따로 갱신해야 합니다.
- 필요한 도구: arping, libcap2-bin, openssl. 검사: bash tools/prepare_camera_admin.sh
  필요한 경우에만: sudo bash tools/prepare_camera_admin.sh --apply
  권한은 검증된 arping의 CAP_NET_RAW에만 적용하며, Python·NIC·Netplan·LTE는 변경하지 않습니다.
- 허브의 카메라 포트 표시는 기존 ARP 캐시와 MAC 학습표 대조입니다. STALE은 과거 캐시이며 새 응답 확인이 아닙니다.
  중복·광·업링크·ED 경로는 확정하지 않고, 포트를 자동 등록·제어하지 않습니다. PoE 제어도 아닙니다.
- 코드 업데이트로 실제 카메라 설정을 바꾸지 않습니다. .camera-admin-backups 백업은 외부에 공유하지 마세요.
- 자세한 순서: manual/카메라_IP_계정_초기등록_사용안내.md

계속 제공되는 기능
- 실시간 · 프로필: H.264 실시간 보기, 지원 Wisenet 카메라 HD/4K 프로필 조회·설정.
  실제 카메라 프로필 변경과 이 녹화기의 RTSP 주소 변경은 각각 별도로 적용합니다.
- 연결 기록: UI 실행 중 약 1분마다 핑 검사. 핑 응답이 영상 수신 성공을 뜻하지는 않습니다.
- 녹화 파일: 카메라·날짜로 찾기, 재생·다운로드, 휴지통 이동·복원. 휴지통도 공간을 씁니다.
- 파일명에 카메라 IP를 넣고 알려진 client·교차로·방향·날씨를 덧붙입니다.
  기존 영상 이름은 바꾸지 않습니다. 계정·비밀번호는 파일명에 넣지 않습니다.

기존 장비 업데이트
1. 녹화와 UI 프로그램을 정상 종료합니다. 브라우저 탭만 닫아서는 종료되지 않습니다.
   서비스 운영 시: sudo systemctl stop goomi-camera-recorder.service
2. recording.json·recording.ini·키를 백업하고 setup.ini·client번호.ini·영상은 유지합니다.
3. 새 프로그램 파일을 교체한 뒤 카메라·시간표·녹화 방식을 확인하고 시험 녹화합니다.
4. 기존 서비스 운영을 계속하려면 검증 후: sudo systemctl start goomi-camera-recorder.service
5. 기존 ffmpeg 설정은 유지됩니다. 동봉 버전을 쓸 때만 ./bin/ffmpeg로 지정하세요.

실행 환경
- Python 3.8 이상, Linux x86_64, 동봉 녹화용 FFmpeg는 glibc 2.35 이상 필요
- ARM 등 다른 환경에는 해당 장비용 FFmpeg를 준비하세요.
- 브라우저는 Tk 없이 사용합니다. 별도 창이 필요하면: sudo apt install python3-tk
- 포트가 사용 중이면: bash 실행.sh --ui-port 8766
- 브라우저 탭만 닫아도 녹화는 계속됩니다. 실행 터미널은 유지해야 합니다.
- 데스크톱 창을 닫으면 확인 후 해당 창에서 시작한 녹화를 정상 종료합니다.
