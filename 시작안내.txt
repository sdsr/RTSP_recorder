RTSP 카메라 녹화 - Linux x86_64 / v2.3 / 2026-11-06

처음 사용하는 경우
1. ZIP을 원하는 폴더에 풉니다. bin/ffmpeg를 포함한 폴더 구조를 유지하세요.
2. RTSP_recorder 폴더의 터미널에서 실행합니다.
   bash 실행.sh
   브라우저 화면이 열립니다. 같은 기능: bash 브라우저실행.sh
   별도 데스크톱 창: bash 실행_GUI.sh (python3-tk 필요)
3. recording.json이 없으면 recording.portable.example.json으로 한 번 생성합니다.
   기존 recording.json이 있으면 그 내용을 보존합니다. 운영 JSON은 ZIP에 넣지 않았습니다.
4. 장비 설정에서 실제 카메라 IP·아이디·비밀번호와 영상 저장 위치를 지정합니다.
   예제 대상은 169.254.130.12 한 대, 아이디 admin, 비밀번호는 비어 있습니다.
   RTSP 포트 554, 영상 경로 /profile2/media.smp는 카메라 설정에 맞게 바꾸세요.
5. 설정 저장 · 적용 → 설정 검사 → 5분 시험 녹화 → 저장 영상 재생 확인 순서로 확인합니다.
6. 시간표 · 날씨를 확인한 뒤 예약 녹화 시작을 누릅니다. PC와 프로그램을 켜 두세요.

배포용 초기 예제
- 한국 시간 06:30-07:30 / 10:00-11:00 / 12:00-13:00 / 17:00-18:00 / 21:00-22:00
- MP4 5분 분할, ./recordings 저장, 자동 삭제 꺼짐, 날씨 조건 꺼짐
- 원본 영상을 재인코딩 없이 저장하며 음성은 저장하지 않습니다.
- record.py가 자체 생성하는 일반 기본값은 30분 분할입니다. 기존 설정값은 바꾸지 않습니다.

v2.3 실시간 보기 · 프로필 관리 · 연결 기록
- 브라우저의 실시간 · 프로필 메뉴에서 저장된 카메라를 선택합니다.
  데스크톱 창은 ‘실시간 보기 · 프로필 관리’ 버튼으로 같은 설정의 웹 화면을 엽니다.
- 실시간 재생은 H.264 영상 전용이며, 별도 녹화 파일을 만들지 않습니다.
  표시된 해상도는 수신 영상 기준, 재생 FPS는 브라우저에서 측정한 값입니다.
- 지원되는 Wisenet 카메라의 HTTPS 443 관리 API로 프로필을 조회·설정합니다.
  녹화·예약 대기 중지 → HD / 4K 변경 내용 확인 → 선택한 카메라에 적용 순서로 진행합니다.
  목표: 2번 HD 1280×720·15fps / 4번 4K 3840×2160·30fps, H.264, 기본 4번.
- 기본 프로필 4번 지정만으로 저장된 /profile2/media.smp 주소가 바뀌지는 않습니다.
  ‘이 프로그램의 녹화 프로필’에서 4번을 고르고 ‘녹화 주소에 적용’을 별도로 누릅니다.
- 프로그램 업데이트 자체는 실제 카메라 설정·녹화 주소를 변경하지 않습니다.
  카메라 프로필을 바꾸면 다른 수신 프로그램에도 영향이 있을 수 있습니다.
- 연결 기록은 UI 실행 중 약 1분마다 핑을 검사합니다(최대64대, 동시4대).
  최근 최대24시간·32,768개 표본을 보관하며 핑 성공이 영상 수신 성공을 뜻하지는 않습니다.
- 카메라 변경 기록: .camera-profile-backups/ / 녹화 주소 변경 전 설정: .recording-profile-backup_*.json
  부분 실패는 자동 재시도·원복하지 않습니다. 결과와 백업을 확인하세요. 설정 백업은 공유하지 마세요.
- 상세 조작: manual/실시간_프로필_사용안내.md

IP 포함 녹화 파일명 (v2.2부터 유지)
- 예: camera_12_ip169.254.130.12_20261105_063000_KST_000000.mp4
- 카메라 식별자와 IP를 넣고, 확인된 client 번호·교차로·방향·날씨는 뒤에 붙입니다.
- 모르는 client 번호·교차로·방향은 Unknown 문구 없이 생략합니다.
- 프로그램 재시작 후 새 녹화부터 적용하며, 기존 영상 이름은 바꾸지 않습니다.
- 웹 목록에서 새 파일은 녹화 당시 주소, 주소가 없는 이전 파일은 현재 설정 주소로 구분합니다.
  현재 설정 주소가 녹화 당시 주소와 같다고 가정하지 않습니다.
- 아이디·비밀번호·URL 쿼리는 파일명에 넣지 않습니다. IPv4는 그대로 표시하며 IPv6·DNS는 정리·축약될 수 있습니다.

브라우저 기능
- 날짜 예약: 매일 같은 시간에 녹화를 끄고 달력에서 날짜를 여러 개 선택한 뒤 저장합니다.
- 녹화 파일 탭: 카메라·날짜로 찾기, 재생, 다운로드, 휴지통 이동·복원.
- 휴지통도 공간을 사용합니다. 보호 중인 파일은 녹화를 중지한 뒤 옮깁니다.
- H.265 등 브라우저가 지원하지 않는 영상은 내려받아 호환 플레이어로 확인하세요.
- 브라우저 탭만 닫아도 녹화는 계속됩니다. 실행 터미널은 유지해야 합니다.
- 데스크톱 창은 닫으면 확인 후 해당 창에서 시작한 녹화를 정상 종료합니다.

기존 장비 업데이트
1. 녹화를 정상 중지하고 프로그램을 종료합니다. 서비스 운영 시:
   sudo systemctl stop goomi-camera-recorder.service
2. recording.json·recording.ini·인증키를 별도 백업합니다. setup.ini·client번호.ini·영상은 유지합니다.
3. 새 코드·스크립트·bin/ffmpeg를 교체하되 기존 설정·키·영상은 지우지 않습니다.
4. 설정 검사와 5분 시험 녹화·재생 확인 후 예약 녹화를 다시 시작합니다.
   기존 서비스 운영을 계속하려면: sudo systemctl start goomi-camera-recorder.service
5. 기존 ffmpeg 설정은 보존됩니다. 동봉 바이너리를 쓸 때만 JSON의 ffmpeg를 ./bin/ffmpeg로 바꾸세요.
   서비스 등록·네트워크 설정은 업데이트가 자동 변경하지 않습니다.

실행 환경
- Python 3.8 이상, Linux x86_64, 동봉 FFmpeg는 glibc 2.35 이상 필요
- ARM 또는 호환되지 않는 환경에서는 해당 장비용 FFmpeg를 준비하세요.
- 브라우저 방식은 Tk 없이 사용합니다. 별도 창이 필요하면: sudo apt install python3-tk
- 다른 관리 화면이 같은 포트를 사용 중이면: bash 실행.sh --ui-port 8766
