02

화면에서 녹화하기

화면은 녹화 현황 / 시간표 · 날씨 / 장비 설정으로 나뉩니다. 처음에는 장비 설정을 확인한 뒤 녹화 현황에서 실행합니다.

작업화면에서 할 일
카메라 연결장비 설정 → 설정 찾기 → 실제 운영 setup.ini 선택
일정 변경시간표 · 날씨 → 시간 구간과 날짜 선택
저장 위치·분할 변경장비 설정 → 저장 폴더와 파일 분할 길이 입력
변경 내용 적용설정 저장 · 적용. 예약 녹화는 재시작하며, 시험 중에는 종료 후 저장합니다.
연결·저장 시험녹화 현황 → 한 번만 녹화 → 5분 시험 녹화
정규 일정 실행녹화 현황 → 예약 녹화 시작
현재 녹화 종료녹화 현황 → 녹화 중지
5분 시험은 날짜·날씨 조건과 관계없이 실행합니다.지정한 시간이 끝나면 자동 종료합니다. 저장된 MP4를 재생해 대상 카메라와 실제 영상을 확인하세요.

상태 읽기

예약 대기는 프로그램이 시간표 또는 날씨 조건을 기다리는 상태입니다. 녹화 중은 실제 카메라 녹화 작업이 실행 중인 상태이며, 영상의 정상 재생까지 함께 확인합니다.

다른 터미널이나 기존 서비스가 같은 폴더에 녹화 중이면 먼저 해당 녹화를 중지합니다. 화면은 자신이 시작한 녹화만 중지합니다.

브라우저 창만 닫아도 녹화는 계속됩니다. 수동으로 UI를 띄운 터미널을 종료하면 그 화면에서 시작한 녹화도 종료합니다. 부팅 자동 실행은 다음 페이지의 서비스 등록 절차를 사용합니다.

03

예보가 맞는 날 전체 녹화

오늘 예보에 비가 한 번이라도 있으면 오늘의 시간표 전체를 녹화합니다. 녹화하는 순간에 실제로 비가 오는지로 판단하지 않습니다.

예보 예시녹화 결과
오후 15시에만 비 예보06–11시 / 12–17시 / 18–22시 모두 실행
당일 비·비/눈·소나기 예보 없음비 조건에서는 그날 녹화하지 않음
오후에 새로 비 예보 확인남은 예약 구간부터 실행. 지난 영상은 복원 불가

시간표 · 날씨에서 조건을 켜고 날씨와 지역을 고릅니다. 여러 날씨 중 하나만 맞아도 충족하며, 한 번 충족한 날은 남은 일정을 유지합니다.

JSON에 미리 추가할 지역·날씨 설정 예
"weather_condition": {
  "enabled": true,
  "region": {
    "sido": "부산광역시",
    "sigungu": "해운대구",
    "eupmyeondong": ""
  },
  "conditions": ["rain"],
  "provider": "open_meteo",
  "met_contact": "",
  "poll_minutes": 30
}

읍·면·동을 비우면 시·군·구 대표 지점을 사용합니다. 읍·면·동까지 선택할 수도 있으며, 제공처마다 예보 모델과 해상도가 다릅니다.

파일명에는 실제 관측 날씨와 구분해 비예보일처럼 표시합니다. 예보 조회 실패 시 새 조건 녹화는 대기하며, 이미 조건을 충족한 당일은 남은 일정을 유지합니다.

04

처음 연결과 자동 실행

개인용은 Open-Meteo 선택

시간표 · 날씨에서 Open-Meteo를 선택하면 API 키·연락처 없이 예보를 사용할 수 있습니다. 무료 API는 개인·비상업용입니다. 사용 조건

MET Norway도 키가 없으며 실제 연락 가능한 개인 이메일 또는 프로젝트 URL을 입력합니다. 기상청은 선택한 발급처의 인증키를 등록합니다. 날씨 조건은 기본 꺼짐입니다.

설정 확인 후 UI와 예약 녹화를 부팅 시 자동 시작
sudo python3 record.py --config recording.json --ui --install

기존 관리 서비스를 UI 방식으로 등록합니다. 화면에서 중지해도 다음 부팅에는 예약 녹화를 다시 시작합니다. 부팅 자동 실행까지 끄려면 아래 명령을 사용합니다.

서비스 중지와 부팅 자동 실행 해제
sudo systemctl disable --now goomi-camera-recorder.service

다른 PC의 브라우저에서 접속

ED_IP를 실제 IP로 변경 · SSH 연결을 유지합니다
ssh -N -L 8765:127.0.0.1:8765 dis@ED_IP

연결한 PC에서 http://127.0.0.1:8765/를 엽니다. UI는 장비의 로컬 주소에만 열리며 외부에 공개되지 않습니다.

서비스 등록을 완전히 제거 · 설정과 영상은 보존
sudo python3 record.py --uninstall

지역 목록 출처: 기상청 동네예보 지점 좌표, 2026년 7월. 인증키를 배포용 JSON이나 소스에 넣지 않습니다.

05

JSON: 이름·날씨·저장 위치

아래는 2026년 10월 15일에만 세 구간을 녹화하는 예제입니다. 실제 날짜·교차로명·날씨·저장 경로로 수정하세요.

recording.json · 전체 예제
{
  "setup_ini": "auto",
  "output_dir": "/home/dis/recordings",
  "intersection_name": "요트경기장",
  "weather": "맑음",
  "recording_dates": ["2026-10-15"],
  "cameras": "auto",
  "time_ranges": [
    "06:30-07:30", "10:00-11:00", "12:00-13:00", "17:00-18:00", "21:00-22:00"
  ],
  "segment_minutes": 30,
  "retention_days": 0,
  "min_free_gb": 5,
  "ffmpeg": "ffmpeg",
  "reconnect_seconds": 10,
  "stall_seconds": 30
}

intersection_name은 파일명의 교차로명, weather는 직접 입력한 날씨입니다. 빈 문자열 ""이면 각각 기존 INI 이름 사용·날씨 제외로 처리합니다.

output_dir는 원하는 폴더 또는 "auto"입니다. 상대 경로는 JSON 폴더 기준이며 서비스 계정이 쓸 수 있어야 합니다. SSD 연결·권한은 저장 위치 절차를 참고하세요.

setup.ini가 여러 개면 setup_ini에 실제 운영 파일의 절대 경로를 적습니다. cameras의 auto는 INUSE=True인 카메라를 선택합니다. JSON에는 주석이나 마지막 항목 뒤 쉼표를 넣지 않습니다.

06

JSON: 실행 날짜와 적용

recording_dates 값녹화하는 날짜
["2026-10-15"]10월 15일에만 시작
["2026-10-15", "2026-10-17"]15일과 17일에 시작
[] 또는 항목 생략기존처럼 매일 반복

날짜는 한국 시간의 녹화 시작일입니다. 15일에 23:00-01:00을 지정하면 16일 01시까지 녹화합니다. 일정이 끝난 뒤 프로그램은 대기하며 자동 종료하지 않습니다.

생성되는 기본 JSON은 날짜 [], 이름·날씨 ""입니다. 날씨는 입력한 고정 문구이며 자동 조회하거나 날짜마다 바뀌지 않습니다. 수정 후 재시작해야 반영됩니다.

설치 없이 실행 · Ctrl+C로 종료
python3 record.py --config recording.json
INI로 설치한 서비스도 JSON으로 한 번 전환
python3 record.py --config recording.json --check && \
  sudo python3 record.py --config recording.json --install
이후 JSON 수정 → 검사 성공 후 서비스 재시작
nano recording.json
python3 record.py --config recording.json --check && \
  sudo systemctl restart goomi-camera-recorder.service
JSON 사용 시 --config recording.json을 명시합니다.생략하면 기존 INI 또는 내장 기본값으로 실행됩니다. 두 설정은 합쳐지지 않으므로 이전 저장 위치·카메라·보관 정책을 JSON에도 옮겨 적습니다.

서비스와 수동 실행을 같은 폴더로 동시에 시작하지 않습니다. 카메라별 이름·날씨 지정 방법과 이전 JSON 형식은 README를 참고하세요.

07

INI 방식: 기본 설정

이 페이지부터는 기존 INI 방식을 유지하는 경우의 절차입니다. 날짜 제한과 직접 입력한 교차로명·날씨는 앞쪽 JSON 방식을 사용합니다.

recording.ini
[CAMERAS]
setup_ini = auto
cameras = auto

[RECORDING]
time_ranges = 06:30-07:30, 10:00-11:00, 12:00-13:00, 17:00-18:00, 21:00-22:00
segment_minutes = 30
output_dir = auto
retention_days = 0
min_free_gb = 5
ffmpeg = ffmpeg
reconnect_seconds = 10
stall_seconds = 30
구분역할
setup.ini기존 ED의 카메라 주소·접속 계정 정보
recording.ini이 녹화 도구의 일정·분할 길이·저장 위치·보관 정책

줄 앞의 ;는 설명용 주석입니다. 주석은 별도 줄에 적고, 항목 이름과 섹션 이름은 예제 그대로 사용합니다. 숫자에는 따옴표를 붙이지 않습니다.

--init-config를 다시 실행해도 기존 파일을 덮어쓰지 않습니다. --install 때 파일이 없으면 기본 설정을 자동 생성합니다. 설정 파일의 이름이나 위치를 바꾸면 새 경로를 지정해 다시 설치해야 합니다.

08

녹화 구간과 파일 길이

[RECORDING] 섹션의 두 항목을 바꾸면 됩니다. 기존 파일에서 해당 항목만 수정합니다.

시간 구간과 파일 분할 설정
time_ranges = 06:30-07:30, 10:00-11:00, 12:00-13:00, 17:00-18:00, 21:00-22:00
segment_minutes = 60
기본 녹화 구간녹화 시간
06:30~07:301시간
10:00~11:001시간
12:00~13:001시간
17:00~18:001시간
21:00~22:001시간

기본은 하루 총 5시간입니다. 표에 지정한 다섯 구간 밖에서는 녹화하지 않습니다. 시간 구간은 쉼표로 나누고 24시간제로 적습니다.

파일 길이 선택

설정파일 길이
segment_minutes = 30약 30분마다 새 MP4
segment_minutes = 60약 1시간마다 새 MP4

녹화 종료 시각과 파일 분할은 별개입니다. 구간이 끝나면 녹화를 종료하므로 마지막 파일은 더 짧을 수 있습니다. 키프레임 간격에 따라 실제 분할 시점이 조금 달라질 수 있습니다.

일정을 바꾸는 예

기존 time_ranges 항목을 교체 · 밤 23시부터 다음 날 01시
time_ranges = 08:00-10:00, 18:00-20:00, 23:00-01:00

시작과 종료 시각이 같은 구간은 허용하지 않습니다. 겹치거나 맞닿는 구간은 이어집니다. 변경 후 설정 검사와 서비스 재시작이 필요합니다.

09

기존 카메라 설정 연결

[CAMERAS]에서 주소를 읽을 파일과 녹화 대상을 정합니다. RTSP 주소를 recording.ini에 다시 입력할 필요가 없습니다.

자동 탐색과 사용 중인 카메라 선택
[CAMERAS]
setup_ini = auto
cameras = auto

setup_ini = auto이면 코드 주변의 config/setup.ini를 먼저 확인하고, 없으면 /home/dis 아래를 검색합니다. 한 개면 사용하고 여러 개면 후보 경로를 표시합니다.

cameras = auto이면 기존 setup.ini의 CAM 섹션 중 INUSE=True인 카메라의 URL을 읽습니다.

여러 설정이 있거나 특정 카메라만 녹화할 때

기존 [CAMERAS] 섹션의 값을 수정
setup_ini = /home/dis/실제프로젝트/config/setup.ini
cameras = CAM1, CAM2
명시한 카메라는 INUSE 값과 관계없이 선택합니다.주소는 선택한 CAM 섹션의 URL을 읽습니다. IP만 있는 CAMADDR나 테스트용 AVI 파일 경로로는 녹화할 수 없습니다.

경로와 프로젝트 이름

프로젝트 폴더가 2025goomi인지 2026goomi인지는 상관없습니다. 같은 이름의 설정이 여러 개면 실제 운영 파일의 경로를 지정합니다. 상대 경로는 recording.ini가 있는 폴더 기준입니다.

설정이나 코드 위치를 바꾸면 서비스에 저장된 경로도 다시 등록해야 합니다. RTSP 계정·암호는 기존 setup.ini에서 관리하며 일반 배포본에 포함하지 않습니다.

10

저장 위치와 보관

[RECORDING]의 저장 항목을 조정합니다. 기본은 찾은 프로젝트의 runtime/scheduled_recordings이며, 별도 SSD는 절대 경로로 지정합니다.

별도 SSD에 저장 · 기존 [RECORDING] 항목 수정
output_dir = /mnt/recordings
retention_days = 0
min_free_gb = 5
실제 마운트와 여유 공간 확인
findmnt -T /mnt/recordings
df -h /mnt/recordings

SOURCE가 의도한 SSD인지 확인합니다. 마운트가 빠진 폴더에 저장하면 시스템 디스크를 사용할 수 있습니다. 서비스 계정에 해당 폴더의 쓰기 권한이 필요합니다.

자동 삭제와 공간 부족

항목동작
retention_days = 0자동 삭제하지 않음
retention_days = 30보관 기간이 지난 관리 대상 파일 정리
min_free_gb = 5남은 공간 5 GiB 미만이면 녹화 중지
보관 일수를 양수로 바꾸면 실제 영상이 삭제됩니다.파일 수정 시각 기준으로 시작 시와 이후 매시간 정리합니다. 현재 쓰는 파일은 제외하며, 기존 MKV 파일도 같은 보관 정책을 따릅니다.

공간이 회복되면 예약 구간 안에서 녹화를 재개합니다. 4 Mbps 카메라 네 대를 기본 5시간씩 녹화하면 약 36 GB/일이므로 실제 비트레이트에 맞춰 용량을 확보합니다.

용량 예시는 십진 GB, 여유 공간 설정은 GiB 기준입니다. 재접속 간격은 reconnect_seconds, 영상 정지 감지 시간은 stall_seconds이며 기본값은 10초와 30초입니다.

INI 설치와 변경 적용

처음 설치 · INI 방식

Python 3.8 이상과 FFmpeg를 먼저 준비합니다. 인터넷 연결 Ubuntu에서는 다음 명령으로 설치할 수 있습니다.

필수 프로그램 준비
sudo apt-get update
sudo apt-get install -y python3 ffmpeg
설정 생성 → 편집 → 검사 성공 후 설치
python3 record.py --init-config
nano recording.ini
python3 record.py --check && sudo python3 record.py --install

설치 시 현재 sudo 실행자의 계정으로 검사하고 서비스를 등록합니다. root로 직접 로그인했다면 --user 실제계정명을 추가합니다. sudo 설치가 새로 만든 INI는 선택한 서비스 계정 소유로 생성됩니다.

이후 설정을 바꿀 때

INI 수정 후 검사·재시작 · 재설치는 필요하지 않습니다
nano recording.ini
python3 record.py --check && \
  sudo systemctl restart goomi-camera-recorder.service
서비스는 INI 파일 경로를 저장합니다.녹화 구간·분할 시간·저장 위치를 수정하고 재시작하면 새 값을 읽습니다. 파일 저장만으로 실행 중인 서비스에 즉시 반영되지는 않습니다.

기존 명령 옵션 방식으로 설치했다면 새 코드와 INI를 준비한 뒤 --install을 한 번 다시 실행해 전환합니다. 기존 INI가 있을 때 설치 명령에 시간·저장 옵션을 함께 주면 오류가 나므로 INI를 편집합니다.

12

한 번만 시험 녹화

최신 record.py로 교체하면 JSON을 편집하지 않고 실행할 때 녹화 시간을 정할 수 있습니다. 지정한 시간이 끝나면 파일을 마무리하고 프로그램도 자동 종료합니다.

검사만 실행 · 실제 카메라 연결이나 녹화는 하지 않습니다
python3 record.py --config recording.json --check
같은 저장 폴더를 사용하는 서비스가 있다면 먼저 중지
sudo systemctl stop goomi-camera-recorder.service
즉시 시작해서 5분만 녹화 · 설치 불필요
python3 record.py --config recording.json --record-minutes 5
오늘 18:30 시작 → 10분 녹화 → 종료 · 한국 시간
python3 record.py --config recording.json \
  --start-at 18:30 --record-minutes 10
JSON의 날짜·시간표는 이번 실행에만 대체합니다.카메라·저장 위치·이름·날씨는 그대로 사용합니다. 설정 파일은 수정하지 않습니다. 실제 영상은 연결 지연이나 끊김만큼 짧을 수 있습니다.

--start-at은 오늘의 아직 지나지 않은 시각만 허용합니다. 이미 지났으면 오류가 나며, 즉시 시작하려면 이 옵션을 생략합니다. 다음 날 자동 반복하지 않습니다.

JSON 없이 실행 · 실제 setup.ini 경로로 수정
python3 record.py \
  --setup-ini /home/dis/실제프로젝트/config/setup.ini \
  --record-minutes 5

JSON 없이 실행하면 옆의 INI 또는 내장 기본값을 사용합니다. 시험 영상을 재생해 확인하세요. 기존 서비스 재개는 설치·운영 절차를 참고하세요.

운영 상태와 영상 확인

서비스 상태와 최근 로그
systemctl is-enabled goomi-camera-recorder.service
systemctl is-active goomi-camera-recorder.service
sudo journalctl -u goomi-camera-recorder.service -n 80 --no-pager
active 상태와 실제 녹화 중인 상태는 다릅니다.UI만 실행 중이거나 시간·날씨 조건을 기다릴 수도 있습니다. 화면의 녹화 상태와 파일 생성·재생을 함께 확인합니다.
저장 구조 예시
저장 폴더/
└── cam1/
    └── 2026-10-13/
        └── run_시작시각_고유번호/
            ├── client29_요트경기장_West_20261013_060000_KST_000000.mp4
            └── client29_요트경기장_West_20261013_063001_KST_000001.mp4

날짜 폴더는 녹화 실행을 시작한 날입니다. 자정을 넘겨도 같은 실행이면 폴더를 유지합니다. 재접속할 때는 새 run 폴더를 만듭니다.

기존 영상은 재인코딩 없이 저장하며 음성·AI 검출 박스·분석 정보는 포함하지 않습니다. MP4는 중단에 대비하는 fragmented 방식이며 재생기와 코덱의 지원이 필요합니다.

장비 중단 중의 영상은 복원되지 않습니다. 예약 구간 안에 복구되면 원래 종료 시각까지 녹화합니다. 한국 시간이 정확한지 확인하세요.

현재 참조 중인 설정 파일 경로와 한국 시간 확인
systemctl cat goomi-camera-recorder.service
TZ=Asia/Seoul date

영상 파일명과 현장 정보

파일명에는 클라이언트 번호, 교차로명, 방향, 날씨, 한국 시간과 순번을 넣습니다. JSON의 이름·날씨를 비우면 기존 INI 이름을 사용하고 날씨는 제외합니다.

JSON에서 이름·날씨를 지정한 예
client29_요트경기장_West_맑음_20261015_060000_KST_000000.mp4
파일명 항목읽는 위치 또는 의미
client29setup.ini의 해당 CAM 섹션에 있는 CLIENTNO
요트경기장JSON의 intersection_name 또는 client29.ini의 NAME
Westclient29.ini → [INTERSECTION] CAMDIR=4
맑음JSON의 weather. 빈 문자열이면 이 부분 제외
20261015_060000_KSTED에서 파일 생성을 확인한 한국 시간
000000해당 녹화 실행 안에서의 분할 순번. 다음 파일은 000001.

CAM1의 CLIENTNO가 29이면 client29.ini를 사용합니다. CAM 번호를 클라이언트 번호로 추측하지 않습니다.

방향: 1 North(북), 2 East(동), 3 South(남), 4 West(서).
5 North-East(북동), 6 East-South(남동), 7 South-West(남서), 8 West-North(북서).

시간은 약 0.2초 간격으로 새 파일을 확인할 때 기록합니다. 카메라 내부의 촬영 프레임 시각은 아닙니다. 처음에는 _pending_000000.mp4 같은 중간 이름이 잠깐 보일 수 있습니다.

정보를 읽지 못해도 영상은 계속 저장합니다.누락된 값은 clientUnknown_cam1, UnknownIntersection, UnknownDirection 등으로 표시하고 경고를 남깁니다. 이름 변경에 실패하면 원래 pending 파일을 보존합니다.

새 record.py로 교체 후 재시작하면 이후 생성되는 파일부터 적용됩니다. 기존 영상 파일을 일괄 변경하지 않습니다. 파일명에 쓸 수 없는 문자는 정리되며 충돌 시 추가 식별자가 붙을 수 있습니다.
