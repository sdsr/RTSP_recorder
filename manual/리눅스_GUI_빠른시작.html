01

폴더 전체를 풀고 화면 열기

Python 3.8 이상, Linux x86_64·glibc 2.35 이상에서 동봉 FFmpeg를 사용합니다. bin 폴더를 함께 유지하세요.

bash 실행.sh

기본은 브라우저 화면입니다. 별도 창은 bash 실행_GUI.sh로 열며 python3-tk가 필요합니다. ARM은 해당 장비용 FFmpeg를 준비하세요.

02

실제 카메라와 저장 폴더 선택

장비 설정에서 카메라 IP를 직접 입력하거나 기존 setup.ini를 선택합니다. 처음 예제는 169.254.130.12 한 대·아이디 admin이며 비밀번호는 비어 있습니다. 실제 접속 정보로 바꾸세요.

데스크톱 창의 같은 메뉴는 장비 · 저장 위치입니다. 직접 IP 방식은 저장 폴더도 지정해야 합니다.

03

설정 저장 → 검사 → 5분 시험

설정 저장 · 적용 → 설정 검사 후 한 번만 녹화에서 5분을 지정합니다. 저장된 영상을 재생해 실제 카메라 연결과 녹화 결과를 확인하세요.

04

시간표 확인 후 예약 녹화 시작

시간표 · 날씨에서 시간을 확인하고 예약 녹화 시작을 누릅니다. 지정 시간 밖에서는 대기합니다. 브라우저의 달력에서는 원하는 날짜를 여러 개 선택할 수 있습니다.

기존 설정을 지키며 업데이트하기

기존 recording.json은 덮어쓰지 않습니다.
새 ZIP에는 운영 JSON이 없습니다. 없을 때만 recording.portable.example.json으로 처음 생성합니다. 코드가 자체 생성하는 일반 기본값은 30분 분할이며, 배포 예제는 5분입니다.

중지 → 설정 백업 → 프로그램 교체 → 시험

녹화를 정상 중지하고 프로그램을 종료합니다. 운영 JSON·INI·인증키를 별도 백업한 뒤 코드·스크립트·bin/ffmpeg를 교체합니다. setup.ini·client번호.ini와 영상은 유지하세요. 다시 설정 검사와 5분 시험 녹화·재생을 확인합니다.

서비스 운영 시 중지: sudo systemctl stop goomi-camera-recorder.service
확인 후 다시 시작: sudo systemctl start goomi-camera-recorder.service

FFmpeg 설정과 서비스는 자동 변경하지 않습니다

기존 JSON의 ffmpeg 값은 유지됩니다. 동봉 버전을 쓰려는 경우에만 ./bin/ffmpeg로 바꾸세요. 경로는 JSON 위치 기준입니다. 서비스 등록과 네트워크 설정도 자동 변경하지 않습니다.

달력과 녹화 파일 관리는 브라우저에서

시간표 · 날씨에서 매일 녹화를 끄고 달력 날짜를 선택합니다. 녹화 파일에서는 재생·다운로드·휴지통 이동·복원이 가능합니다. 휴지통도 공간을 사용하며, 보호 중인 파일은 녹화를 중지한 뒤 옮깁니다.

창을 닫으면 어떻게 되나요?

브라우저 탭을 닫아도 녹화는 계속되지만 실행 터미널은 유지해야 합니다. 데스크톱 창은 최소화해도 계속 녹화하며, 종료하면 확인 후 그 창에서 시작한 녹화를 정상 종료합니다. 앱 메뉴 아이콘은 데스크톱 창을 엽니다.

날씨 조건은 필요한 경우에만 켜세요

개인용 Open-Meteo는 API 키 없이 지역과 날씨를 설정합니다. 그날 예보에 선택한 날씨가 한 번이라도 있으면 남은 예약 시간대를 녹화합니다. 이미 지난 영상은 복원할 수 없습니다.

최신 기능은 README와 이 v2.1 안내를 기준으로 사용하세요. 기존 ED 유지보수 상세 설명서는 이전 화면·시간표를 포함한 참고 자료입니다. 원본 H.264/H.265를 재인코딩 없이 저장하며 브라우저 재생은 코덱 지원에 따라 달라집니다.
