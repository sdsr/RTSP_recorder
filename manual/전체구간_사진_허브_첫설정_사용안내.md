# 첫 설정·전체 구간 녹화·사진·허브 관리

RTSP Recorder v2.4 · 2026-11-17

이 안내는 업데이트한 프로그램의 사용법입니다. 코드 설치만으로 실제 카메라·허브 설정이나 PC 네트워크가 변경되지는 않습니다. 이전 실시간 보기·프로필 관리·핑 이력과 IP 포함 파일명도 계속 사용할 수 있습니다.

## 처음 실행하고 카메라 등록하기

압축을 푼 `RTSP_recorder` 폴더에서 실행합니다.

```bash
bash 실행.sh
```

브라우저 대신 별도 데스크톱 창은 `bash 실행_GUI.sh`로 실행하며 `python3-tk`가 필요합니다.

새 설치에는 특정 카메라 IP·아이디·비밀번호·날씨 지역이 들어 있지 않습니다. 기존 `recording.json`이 없다면 카메라 목록이 비어 있는 파일을 만들고 **장비 설정**을 먼저 엽니다.

1. **카메라 IP 직접 입력**에서 실제 IP를 등록하거나 **기존 setup.ini 사용**으로 운영 파일을 선택합니다.
2. 인증이 필요한 카메라는 실제 아이디와 비밀번호를 입력합니다. `admin`을 자동으로 넣지 않으며 인증 없는 카메라는 계정을 비워 둘 수 있습니다.
3. RTSP 포트·영상 경로·저장 폴더·시간표를 확인하고 **설정 저장 · 적용**을 누릅니다.
4. **설정 검사 → 5분 시험 녹화 → 저장 영상 재생 확인**을 진행한 뒤 예약 녹화를 시작합니다.

카메라 등록 전에도 저장 위치·시간표 등의 초안을 저장할 수 있습니다. 카메라가 없는 상태에서는 녹화·실시간 재생·사진 캡처를 시작하지 않습니다. 날씨 조건을 켜거나 예보를 조회할 때는 **시간표 · 날씨**에서 지역을 직접 선택합니다. 날씨 기능을 사용하지 않는다면 지역을 비워 두어도 됩니다.

기존 설정 파일은 보존합니다. 저장된 IP가 옛 예제와 같더라도 실제 운영값일 수 있으므로 자동 삭제하지 않습니다. 빈 상태에서 새로 설정해 보려면 기존 운영 폴더를 지우지 말고 새 폴더에 배포본을 풀어 실행하세요.

## 예약 구간마다 한 파일로 녹화하기

**장비 설정 → 녹화 파일 저장 방식 → 예약 구간마다 한 파일**을 선택합니다. 설정 파일에서는 `"recording_mode": "window"`입니다. 새 설치의 기본 모드도 `window`입니다.

- `06:30–07:30`은 약 1시간 파일 하나, 2시간 구간은 약 2시간 파일 하나로 저장합니다.
- 이 모드에서는 기존 `segment_minutes` 값이 남아 있어도 분할에 사용하지 않습니다.
- 카메라 연결이 끊기거나 프로그램이 재시작되면 복구 후 새 파일이 생성될 수 있습니다.
- 서로 겹치는 시간 구간은 합쳐집니다. 끝과 시작만 맞닿은 구간은 경계에서 새 파일을 만듭니다.
- H.264/H.265 원본을 MP4로 저장하며 재인코딩하거나 기존 파일을 합치지 않습니다.

분할이 필요하면 **일정 길이로 파일 분할**을 선택하고 분 수를 입력합니다. JSON 예:

```json
"recording_mode": "split",
"segment_minutes": 30
```

이전 설정에 `recording_mode`가 없고 `segment_minutes` 또는 `segment_seconds`가 있으면 기존 분할 동작을 유지합니다. 코드 교체만으로 모든 기존 설정이 전체 구간 모드로 바뀌는 것은 아닙니다. 사용 중인 화면에서 현재 모드를 확인하고 선택해 저장하세요.

**한 번만 녹화**에서는 저장된 카메라 한 대를 선택해 시험할 수도 있습니다. 이 선택은 해당 시험에만 적용하며 예약 녹화의 카메라 목록은 바꾸지 않습니다.

```bash
python3 record.py --config recording.json --record-minutes 5 --record-camera camera_12
```

`camera_12`는 예시입니다. 화면에 저장된 실제 카메라 이름을 사용하세요.

## 카메라 사진을 PNG로 저장하기

브라우저의 **이미지 캡처**에서 카메라와 프로필을 고른 뒤 **이미지 캡처**를 누릅니다. 실시간 화면에서도 **현재 카메라 이미지 캡처**를 사용할 수 있습니다. 사진 해상도는 실제 캡처 결과에 표시됩니다.

사진 변환에는 H.264/H.265 디코더와 PNG 인코더가 있는 일반 FFmpeg가 필요합니다. Ubuntu에 없다면 운영자가 설치합니다.

```bash
sudo apt install ffmpeg
```

카메라 RTSP 연결·인증은 기존 녹화용 FFmpeg가 담당하고, 받은 한 프레임을 일반 FFmpeg가 PNG로 변환합니다. 동봉 녹화 전용 FFmpeg나 카메라 비밀번호·프로필 설정은 바꾸지 않으며 프로그램이 패키지를 자동 설치하지 않습니다.

사진은 영상 저장 폴더와 별도로 **`recording.json` 옆의 `snapshots/카메라/날짜/`**에 저장합니다. 목록에서 확인하거나 PNG를 다운로드할 수 있습니다. 목록 기록 실패 안내가 나오면 완성된 PNG는 보존되므로 해당 폴더와 저장 공간을 확인하세요. 사진 기능은 Linux ED에서 사용합니다.

## 지원 허브 조회와 변경

**허브 관리**에서 실제 관리 IP·계정, ED의 기존 관리 인터페이스와 소스 IP를 직접 입력합니다. 프로그램이 PC에 IP나 VLAN 인터페이스를 새로 만들지 않습니다. 관리 경로는 `enp2*` 카메라 NIC 또는 그 NIC에서 파생된 VLAN 인터페이스여야 하며 enp3/LTE 기본 경로를 사용하지 않습니다.

쓰기 기능은 NEXTU NTK-9528 계열 중 모델 식별값 **`POE9728MDTL2`**, 펌웨어 **`V200SP10241024`**에 한정됩니다. 다른 모델이나 확인할 수 없는 펌웨어는 임의로 변경하지 않습니다. 먼저 상태를 조회하고 실제 CPU MAC을 확인해 저장합니다.

1. 포트 상태와 보호 사유를 확인합니다.
2. 허용된 카메라 포트의 켜기·끄기·잠깐 끊었다 연결하기, 기존 카메라 VLAN 선택 또는 관리 IP 변경 내용을 미리 봅니다.
3. 예상 변경과 영향 범위를 확인한 뒤 명시적으로 적용합니다.

ED 연결 포트, 광 업링크, 링·묶음 연결, 관리/제어 VLAN 등은 보호합니다. 카메라용 VLAN은 허브에 이미 존재해야 하며 새 VLAN 생성·광 포트 구성·링 제어는 변경하지 않습니다. 대상 VLAN에는 ED·센터로 이어지는 경로가 있어야 합니다.

**포트 껐다 켜기는 데이터 통신 연결 제어이며 PoE 전원 재인가가 아닙니다.** 포트가 꺼진 동안 해당 카메라의 녹화와 센터 영상이 끊깁니다. 관리 IP는 현재 관리 대역 안에서만 변경합니다. 변경 전 설정과 결과는 설정 폴더 아래 `switch_backups`에 저장합니다. 실패 시 결과를 확인하고, 관리 연결 자체가 끊긴 경우에는 원격 복구가 보장되지 않습니다. 허브 설정 백업은 외부에 공유하지 마세요.

## 업데이트 후 확인

녹화와 UI 서버를 종료한 뒤 프로그램 파일을 교체하고 기존 설정·키·영상은 보존합니다. 서비스 운영은 검증 전에 자동 시작하지 않도록 현재 실행 상태를 확인하세요. 브라우저 탭만 닫아도 UI 서버는 계속 실행될 수 있습니다.

재실행 후 **Ctrl+Shift+R**로 화면을 갱신하고 카메라·시간표·녹화 방식을 확인합니다. 실제 카메라 접속·사진 변환·허브 모델 지원은 적용할 장비에서 확인해야 합니다. 이전 PDF에는 예전 초기값과 화면이 포함되어 있으므로 최신 설정은 이 안내와 [README](../README.md)를 기준으로 사용하세요.
